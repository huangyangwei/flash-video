## Why

在抖音直播间抢码时，抖音 Web 播放器为保证流畅内置了数秒缓冲且缓冲只涨不缩，导致我看到的画面比别人慢几秒，错过抢码时机。需要一个自用的低延迟播放页：播放同一条公开的 `.flv` 拉流地址，用最小缓冲 + 可调追帧把延迟压到 ~1.5s，比抖音 Web 播放器的观众快 2~4 秒。

## What Changes

- 新增一个 Web 播放页：粘贴从抖音页面抓取的 `.flv` 地址即可播放
- 播放核心采用 mpegts.js，关闭/压最小发送侧缓冲（`enableStashBuffer: false`、`stashInitialSize: 384`）
- 内置追帧逻辑：缓冲水位超过阈值时变速播放（1.05x~1.5x），超过跳帧阈值时直切最新关键帧
- 追帧参数全部用户可调：总开关、变速触发阈值、变速倍率、跳帧阈值（可禁用）
- 断流处理：`.flv` 地址带签名有时效，播放中断时提示重新粘贴新地址
- 不做：服务器端、多观众、自动抓流（地址手动抓取）、RTC/自建传输协议

## Capabilities

### New Capabilities

- `low-latency-playback`: 粘贴 `.flv` 地址后以最小缓冲播放直播流；缓冲只减不增；断流时给出重新贴入地址的提示；目标端到端延迟 ≤1.5s
- `catch-up-control`: 追帧行为可配置——总开关、变速触发阈值（缓冲水位 ms）、变速倍率（1.05x~1.5x）、跳帧阈值（ms，可设为禁用）；激进追帧由跳帧承担主力，变速只做细微修正

### Modified Capabilities

（无——本项目为全新项目，无既有 spec）

## Impact

- 全新前端项目（Web 页面），无既有代码受影响
- 新增依赖：`mpegts.js`（播放核心）
- 无服务器、无后端 API；纯静态页面即可运行
- 上游不受控：延迟下限受抖音 GOP/TCP 制约（~0.5-1s）；地址签名过期属正常现象，靠重新贴入解决
