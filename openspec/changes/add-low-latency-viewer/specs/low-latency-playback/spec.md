# low-latency-playback — Delta

## Purpose

让用户粘贴从抖音页面抓取的 `.flv` 直播流地址后，以远小于抖音 Web 播放器的缓冲播放同一条流，从而比其他观众更早看到画面；流中断时能明确告知并引导重新贴入新地址。

## ADDED Requirements

### Requirement: 粘贴地址即可播放
系统 SHALL 提供一个输入入口，用户粘贴 `.flv` 拉流地址后即可开始播放对应直播流，无需任何服务器或后端参与。

#### Scenario: 粘贴有效地址
- **WHEN** 用户粘贴一条有效且未过期的 `.flv` 地址并确认
- **THEN** 页面开始播放该直播流画面（音频默认静音，见 catch-up-control）

#### Scenario: 粘贴无效地址
- **WHEN** 用户粘贴的地址无法建立连接或格式不正确
- **THEN** 页面展示可读的错误提示，且不崩溃、不循环静默重试

### Requirement: 最小缓冲播放
系统 SHALL 以最小化缓冲的方式播放直播流：禁用发送侧预缓冲（stash），且运行期间缓冲水位 MUST NOT 因非网络抖动原因持续增长。目标端到端延迟为 ≤1.5s（受上游 GOP/传输制约，地板约 0.5~1s）。

#### Scenario: 播放稳定后延迟低于抖音 Web 播放器
- **WHEN** 播放稳定运行超过 1 分钟
- **THEN** 播放器缓冲水位保持在 1s 量级以内，画面明显先于同一房间抖音 Web 播放器的画面出现

#### Scenario: 网络抖动后缓冲不永久膨胀
- **WHEN** 网络出现短暂抖动导致缓冲水位上升
- **THEN** 网络恢复后缓冲水位回落到目标值附近，而不是停留在高位

### Requirement: 断流提示与重贴地址
由于 `.flv` 地址带签名有时效，当流中断且无法自动恢复时，系统 SHALL 明确提示"地址已失效/流已中断"，并引导用户重新粘贴新地址；重新粘贴后 MUST 恢复播放且从直播边缘（最新画面）开始，而不是从历史缓冲处继续。

#### Scenario: 地址过期导致断流
- **WHEN** 播放中流因地址签名过期或上游中断而停止
- **THEN** 页面展示明确的断流提示，并提供重新贴入地址的入口

#### Scenario: 重新贴入后从直播边缘恢复
- **WHEN** 用户在断流提示后粘贴一条新地址
- **THEN** 播放从当前最新画面恢复，不回放中断前的历史内容
