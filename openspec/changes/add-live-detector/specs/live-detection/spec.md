# live-detection — Delta

## Purpose

提供开播监测：检测指定抖音房间是否开播，开播即提取 flv 地址交给播放页自动开播。轮询配置在播放页设置（轮询引擎内嵌本地 dev server 的 Node 侧，规避浏览器 CORS），`npm run watch` CLI 保留为备用入口。

## ADDED Requirements

### Requirement: 播放页配置监测
播放页 SHALL 提供监测设置面板：直播间链接或房间号输入、轮询间隔输入、开始/停止开关。配置变更 MUST 自下一轮轮询起生效，无需重启；监测状态（当前房间、是否直播中、最近一次轮询结果与失败信息）MUST 在页面可见。轮询 MUST 运行在本地 dev server 的 Node 侧（浏览器页面 MUST NOT 直接请求抖音页面）。

#### Scenario: 粘贴链接开始监测
- **WHEN** 用户在页面监测面板粘贴直播间链接并点击开始
- **THEN** 面板显示监测中，dev server 侧开始轮询该房间，状态随轮询结果更新

#### Scenario: 配置即时生效
- **WHEN** 监测运行中用户修改轮询间隔或更换房间链接
- **THEN** 自下一轮轮询起按新配置执行，无需刷新页面或重启服务

#### Scenario: 停止监测
- **WHEN** 用户点击停止
- **THEN** 轮询停止，面板显示已停止，不再触发自动开播

### Requirement: 开播判定与流地址提取
轮询引擎 SHALL 通过解析房间页 HTML 内嵌数据判定开播状态，并在"未开播→直播中"跳变（含启动监测时已在直播）时提取可用 flv 地址暴露给页面；监测期间的同状态后续轮询 MUST NOT 重复触发开播动作；轮询失败 MUST NOT 改变跳变沿记忆（恢复后仍能正确触发）；解析失败 MUST NOT 误报开播。

#### Scenario: 跳变沿检测到开播
- **WHEN** 轮询观察到状态从未开播变为直播中
- **THEN** flv 地址在监测状态中可见，页面自动开始播放该地址

#### Scenario: 启动监测时已在直播
- **WHEN** 用户对一个正在直播的房间启动监测
- **THEN** 首轮轮询即提取到 flv 地址并触发页面自动开播（刚开就想看就看）

#### Scenario: 一直未开播
- **WHEN** 连续多次轮询房间均为未开播状态
- **THEN** 监测状态显示未开播，不触发自动开播、不误报

### Requirement: 失败退避与熔断
轮询失败（网络错误、非 200、解析失败）时，引擎 SHALL 按递增退避重试（封顶 5 分钟），失败信息 MUST 在页面可见；持续失败 MUST 保持退避节奏而非放弃，用户可随时停止。

#### Scenario: 轮询失败退避
- **WHEN** 某次轮询超时、非 200 或解析失败
- **THEN** 页面显示失败原因与退避等待，恢复后继续按用户间隔轮询

### Requirement: CLI 备用入口
`npm run watch` SHALL 提供与页面监测等价的轮询能力：`--room` 接受完整直播间链接或纯房间号，未提供时启动交互询问（回车用默认房间）；`--interval` 自定义间隔；开播跳变沿以系统默认浏览器打开深链 `/#/?url=<flv地址>`（origin 可用 `--origin` 覆盖）；失败退避策略与页面监测一致。

#### Scenario: CLI 粘贴链接启动
- **WHEN** 用户在交互提示处粘贴 `https://live.douyin.com/134525032676?from=xxx` 并回车
- **THEN** 脚本提取房间号并开始轮询，控制台打印解析出的房间与生效间隔

#### Scenario: CLI 检测到开播唤起播放页
- **WHEN** 脚本检测到开播并成功提取 flv 地址
- **THEN** 系统默认浏览器被打开到带 `#/?url=` 参数的播放页深链
